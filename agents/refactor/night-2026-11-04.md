## Flow

- **Track A (S0):** one capture subagent ([roles/capture.md](roles/capture.md)), started right after setup. It runs alongside Tracks B and C.
- **Track B:** one item at a time:
  1. an implementer subagent ([roles/implementer.md](roles/implementer.md)) makes the change and runs its checks;
  2. a reviewer subagent ([roles/reviewer.md](roles/reviewer.md)) reviews it independently, without the implementer's reasoning;
  3. a problem either is fixed, or the item is dropped as `rules.md` (Git) says: its diff saved as a patch, then `git checkout -- <its files>`. Its State gets the reason;
  4. when both steps pass, the main thread commits it together with its catalog State line, then builds the per-commit host and replayer of Pokopia and DK into `<work>/runs/hosts/head-<hash>/` (`commands.md`) before the next implementer starts.
- **Overlap:** while one item is being implemented, read-only subagents may already study the next one.
- **Pipelined review (from 05:35, to fit S2 and later into the night):** when implementer N reports ready, the main thread saves its diff as `/Volumes/Hangar/Games/overnight/patches/<N>.patch` and starts implementer N+1 at once, on top of N's uncommitted diff; N's reviewer runs meanwhile. N+1 measures against `<work>/runs/hosts/cand-<N>/`. N is committed with `git apply --cached <N>.patch` plus its agents files, so N+1's changes stay out of N's commit. A rejected N leaves the tree with `git apply -R <N>.patch` (N+1 rebases its diff and re-runs its checks), and its State gets the reason.
- **Every 4 kept items:** the main thread boots Pokopia and DK for 120 s through the guard with the `head-<hash>` hosts and the base boots' keys and frames, and compares the screenshots with `<work>/shots/base/`.
- **Once the corpus exists:** items committed before it are replayed against it. Any that fails is reverted with `git revert`, which keeps history; never reset.
- **A failed stage:** a stage that cannot meet its criterion stops there. Its commits stay only if each passed its own checks. Work moves on to the next stage that does not depend on it. HT and Track C do not depend on S2 / S2b; S3 needs S2 and S2b settled (each item kept or reverted).
- **Track C (architecture docs):** three architecture subagents, A, B and C, write the files of `agents/architecture/` as its README assigns them. They are read-only on source and each writes only its own files. Then:
  - a reviewer subagent checks 10 statements per file against the code (`reports/<ts>-architecture-review.md`);
  - a wrong statement is fixed by that file's writer;
  - the main thread sets each file's State in `agents/architecture/README.md` and commits the folder (`docs(agents): ...`);
  - the relative links must pass `dm/tools/tests/test_docs.py`.

  S3 waits for `nvn-state.md` to be reviewed.
- **Searches:** callers, failure causes and frames go to search subagents ([roles/search.md](roles/search.md)).
- **Before each summary:** one reviewer in full-diff mode ([roles/reviewer.md](roles/reviewer.md)) reviews `<BASE>..refactor` (`reports/<ts>-final-review.md`).
- **Architecture writers:** [roles/architect.md](roles/architect.md); their reviewer uses the architecture mode of [roles/reviewer.md](roles/reviewer.md).
