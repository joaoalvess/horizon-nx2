## Findings

### 1. `-Wl,-export_dynamic` in the host: needed to keep `DM_NVN_UB @set:` working, but it turns off ThinLTO internalization for the whole host (design/perf; not a defect)

- Where: `dm/host/Makefile:18`, `dm/gfx/tests/Makefile:14`.
- Why it is needed: `ub_var` (`dm/gfx/nvn/nvn_mtl.m:1432-1437`) looks up any int global by name with `dlsym(RTLD_DEFAULT, nm)` on the Mac. `t_ub` tests this with `g_t_ub_var` / `g_t_ub_var2` (`dm/gfx/tests/t_ub.m:9,13`). That is the only runtime symbol lookup in `dm`: `probe.c:135` `dladdr` reads the nlist table, which keeps local symbols. Without the flag, ld64 lets LTO internalize every global of a main executable that no Mach-O object references. `dlsym` then returns NULL, and a global that is never written may also be constant-folded.
  - Failure without the flag: `DM_NVN_UB="a=@set:g_foo=1,…"` on the Mac logs "global variable not found" for every unregistered switch (today only iOS behaves like that), and `t_ub`'s "variable 1/2" checks fail.
  - The flag restores what a non-LTO executable already does: the `-O1` binary exports 2,039 globals, the new one 2,056.
- What it is not needed for: symbols that only module asm references. `dm/host/tests/build/t_fs` and `t_bigstack` link `hle_bigstack.c` without the flag, export only 9 and 5 globals (so LTO did internalize), and still keep `_dm_bigstack_top` (referenced only by `bl _dm_bigstack_top`, `hle_bigstack.c:61`) as `T`. `.S` references (`nvn_entry.S:14` → `nvn_unimpl_c`, `entry.S:110` → `dm_gate_nested`) come from Mach-O objects, which the linker preserves on its own.
- Cost: none of the host's ~2,000 globals can be internalized. Cross-module importing still happens: `dm_bigstack_caller` is inlined into `h_au_Start` (the code compares x30 with `_dm_bigstack_ret`). What is lost:
  - the inliner's last-call-to-a-local bonus for single-caller extern functions;
  - deletion of out-of-line copies and of unused externs;
  - IPSCCP / GlobalOpt on extern functions and variables.

  That is a large part of ThinLTO's gain. B1's acceptance ("replay CPU lower than base") measures only the combined effect.
- Narrower options (for the main thread or the user; none required for this item):
  - (a) Drop the flag from the host and use the registration table in `ub_var`, the mechanism the code already documents for iOS. This changes a Mac diagnostic, so it is the user's call.
  - (b) `-Wl,-exported_symbol,_g_*` (ld64 wildcard). It keeps the `g_` globals exported and preserved, and lets LTO internalize the rest. Unverified: that ld-prime treats wildcard export patterns as LTO must-preserve.
  - (c) In `dm/gfx/tests`, only `t_ub` needs the flag (rule at `Makefile:201`). Putting it in the shared `CFLAGS` is acceptable while the host keeps it, because the tests then link the way the host does. If the host drops it, the flag moves to `t_ub`'s rule, or the two test globals get `__attribute__((used))`.
- Suggested check: measure replay CPU once with and once without the host flag before deciding whether (a)/(b) is worth it.

## Checks that hold

### `__builtin_return_address` / `__builtin_frame_address`: every reader is `noinline`

`rg -n '__builtin_(return|frame)_address' dm` gives 32 sites, all inside a function that now carries the attribute or already did:

Notes on coverage:
- No macro expands to either builtin. `hle.h:50` is a comment.
- No inline asm reads x29, x30 or sp. The only register read is `loader.c:41` (`tpidrro_el0`).
- How the attribute attaches: in each macro the prefix lands on the first (forward) declaration, and the definition inherits it.

Callers that inlining could reach:
- The value is always evaluated in the entry function and passed down as an argument: `tex_snap`, `rec_downsample`, `au_*_at`, `ai_open`, `module_of`, `dm_bigstack_caller`. Inlining those callees is harmless.
- The only reader that depends on its caller's frame is `diag_abort`, through `frame_address(1)`. It and all three of its callers are `noinline`.
  - In the LTO `dmhost`, `h_diag_Abort0` builds a frame record and calls `diag_abort` with `bl` (`stp x29, x30, [sp,#-16]!` … `bl _diag_abort`), not a tail call, so `frame_address(1)` still lands on the entry's frame.
  - `h_au_Start`, `h_nvnCommandBufferDispatchCompute` and `h_nvnWindowSetPresentInterval` copy x30 right after the prologue.
- For the host the attribute is redundant on the static, table-registered entries: no direct caller exists for them to be inlined into. It does matter for the tests that call them directly (`t_audio.c:64-70`, `t_audio_spsc.c:102-142`, `t_bigstack`'s `probe`). It is cheap and is what S1 asks for.

### `.alt_entry`: necessary, correct and sufficient

The linker does reorder atoms inside one file's module asm under ThinLTO:
- In the LTO `dmhost`, `hle_gl.m`'s `_bs` stubs are out of source order, and `gl_stub_entry` (0x1000a7c38) lies after `_gl_stubs` (0x10009fb20).
- In the `-O1` binary, source order is kept: `gl_stub_entry` 0x1000740f0 < `_gl_stubs` 0x100074108, and enter / ret / top are in order.

Without `.alt_entry`, `_dm_bigstack_ret` starts an atom of its own (C files always end with `.subsections_via_symbols`). Two paths depend on adjacency:
- the fall-through after `blr x16` (`hle_bigstack.c:77`);
- `cbz x17, 1f` (`hle_bigstack.c:72`) into the code after `_dm_bigstack_ret`. `1:` is a temporary label, so the assembler resolves the branch to a fixed offset: there is no Mach-O branch19 relocation, and the linker never sees the edge.

Failure if the atoms were split: every `HLE_FORCE_BIG` / `VKB` / `GLB` call that switches stacks returns into unrelated code, and the no-switch path branches into whatever atom sits at that offset.

With `.alt_entry` the whole block is one atom:
- current `dmhost`: `_dm_bigstack_enter` 0x10001d12c, `_dm_bigstack_ret` = enter + 0x78, `cbz x17, 0x10001d1b8` = the `1:` path, next symbol at 0x10001d1c4;
- `t_bigstack`: `_call_on_site` = `_call_on` + 0x14, the address the test compares against.

Dead-stripping: neither the host nor the tests that link `hle_bigstack.c` pass `-dead_strip`, and a merged atom is kept whole by any reference to it.

Other module asm in `dm`, none exposed the same way:
- The stubs in `hle.h:46`, `hle_vk.m:49`, `hle_gl.m:53` and `t_pctl.c:13` are single atoms that end in `b` / `br`.
- `_gl_stubs` → `gl_stub_entry` (`hle_gl.m:2040`) branches to a non-temporary symbol, so the linker relocates it. The LTO binary shows `b gl_stub_entry` correctly retargeted after the reorder, and `gl_stub_entry` ends in `b _gl_stub_c`.
- `nvn_capture.c:6` holds only `.linker_option` (`libcompression` still links: `otool -L`).
- The `.S` files (`entry.S`, `nvn_entry.S`, `nvn_thunks.S`) have no `.subsections_via_symbols`, so each section is one atom, and LTO does not touch them.

These two edits are outside the catalog row's file list but follow directly from the flag change. Name them in the commit message. The mechanism (module asm that falls through or uses a temporary-label branch across a global label needs `.alt_entry`, because the linker reorders atoms) is worth an entry in `docs/reference/` later.
