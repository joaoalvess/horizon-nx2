## Checks

### Lifetime of arena buffers once callers hold only `cpu`
- An `NvArena` owns its buffer (strong ivar, `:5350`). The arena is held by `g_cur_arena` and `g_sub_arenas` while a submission records (`:5380-5381`). `arena_commit` (`:5374`, called from the final `mtl_sub_commit` at `:1635`) moves it to `g_arenas` with that submission's fence. Segment commits (`:11560`) and `mdi_wait` (`:10103`) do not call `arena_commit`, so the arena keeps fence 0 until the submission's last commit. `arena_new` (`:5356`) recycles only arenas with `fence && fence <= g_done`. CPU writes therefore land only in an arena no GPU work still reads, as before.
- Nothing in encode_args kept a buffer alive past the function before this diff: `db` and `ab` were locals, released at scope end. The single exception was the strong `sh->ab_buf`. The `cpu` writes (`:8143`, `:8151`, `:8202`, `:8211`) are synchronous and finish before `encode_args_` returns, so they need no reference.
- `g_cur_arena` between the allocation and the write: in each branch the `arena_alloc` and its `cpu` write are adjacent. The only code between the DRV0/DRV2 allocation (`:8151`) and its `slots`, `USE` and `g_c0_dim_buf` uses (`:8171`, `:8192-8193`) is `c0_ssbo_base`, `c0_sample_rows`, `dm_sdk_ounce`, `C2_LOCAL` and `memcpy`. None of them allocates from the arena. The arena-allocating calls in the loop (`ubd_shadow` `:1172` and `ubp_get` `:1317`, under NVN_RB_CBUF) sit in other bindings' branches. HEAD already computed `slots[aid] = g_cur_arena->gpu + doff` after the fill, so the diff adds no assumption: CPU and GPU addresses now come from the same arena, where before the CPU side used `db`. `g_cur_arena` is written only on the submit thread (`arena_alloc`, `arena_begin`, `arena_commit`). No other thread allocates.
- Arena release: only `arena_begin`'s idle trim frees buffers (`:5372`, arenas over `ARENA_KEEP`, at least `ARENA_IDLE` submissions after their completed fence). See the `ab_buf` section for the one pointer that can outlive it.

### `cpu == buf.contents`
- An arena's buffer is assigned in one place only, `arena_new` (`:5358`): `newBufferWithLength:` with `MTLResourceStorageModeShared`, which always has a CPU mapping that does not move. `cpu` is taken right after the `MDIE` nil check (`:5360`). Recycling (`:5357`) keeps the same `NvArena`, `buf` and `cpu`. No code grows or replaces an arena's buffer: a request that does not fit takes another arena (`:5379-5381`). `rg 'NvArena|->buf ='` finds no other constructor or writer, including in `nvn_geometry.inc`, `nvn_feedback.inc`, `nvn_rec.h` and the tests.

### `__unsafe_unretained ab_buf`
- Readers: production has one, the reuse test `sh->ab_buf &&` (`:7946`). It is a plain load and nil compare: ARC sends no message, so a dangling value is harmless there. The other readers are `t_feedback.m:66,74` and the new test's `block_of` / `compute_case` (`t_arena_args.m:11-12,29-31`). All of them send `contents`, `gpuAddress` or `length` within the submission that encoded the block, while its arena is still in `g_sub_arenas`, so the buffer is alive. `g_c0_dim_buf` was already `__unsafe_unretained` (`:7919`). It is reset before each dispatch's encode and used right after it (`:10893-10897`).
- It can dangle. While a large scratch arena is `g_cur_arena` (geometry capture, `nvn_geometry.inc:129,652`), later small allocations, argument blocks included, fill the rest of it. If a shader's last block landed there and that shader does not encode again before `arena_begin` trims the arena (`:5372`), its `ab_buf` points at a freed buffer. Its next encode fails `ab_pass == g_pass.serial` (the serial grows at each `rp_begin`, `:4211`) and overwrites the pointer, so nothing dereferences it. At HEAD, the strong ivar kept that up-to-256 MB buffer alive after `res_remove` until the shader re-encoded, so this diff frees it sooner. A future reader that sends `ab_buf` a message outside the encoding submission would crash. Note this in the reference entry (below), since the rules forbid a code comment.

### `USE` and residency
- `USE` (`:7956`) evaluates its buffer only under `DM_RES_CHECK` (`res_check`, `:249`). `USE(db)` became `USE(g_cur_arena->buf)` at `:8144`, `:8193` and `:8204`. Since no allocation happens between, it names the same buffer. Residency comes from `res_add` in `arena_new` (`:5360`), and that is unchanged. Before the diff, `bind_args` already ignored `ab` and the argument block itself was never `USE`d. That is still the case. Both `bind_args` callers (`:7947`, `:8212`) are updated, and there are no others in `dm/`.

### The new test (`dm/gfx/tests/t_arena_args.m`)
- It catches a wrong pointer on the converted paths. `compute_case` checks the GPU's own reads of the push block, c0 (dispatch counts at 0x200, storage-buffer row at 0x310), c2 (texture words at 0x20) and the border block (mask and factors), all through the argument block. The offsets match `dmsh_abi.h`. A `cpu` that is unset, stale, offset, or from another arena makes those reads wrong or faults the submission. The second submission uses a different seed and asserts a recycled arena (`g_arena_made` unchanged), so a stale write would show. `reuse_case` reads the c0 block through `ab_buf.contents`, independently of `cpu`, so a `cpu`/`contents` mismatch fails there too. It also checks same-pass reuse without allocation, the rebind to `ab_gpu`, a new block on a base-instance change, and a new block in a new pass. `alloc_case` checks the NULL out-parameter path and an overflowing allocation.
- Makefile: the build rule and `check_t_arena_args: RUN_ENV = MTL_DEBUG_LAYER=1` follow the `t_feedback` pattern. `RUN_TESTS` is a wildcard and the binary matches `.gitignore`'s `t_*`, so no other line is needed.

### Scope and leftovers
- No comments added or removed. On the `ab_buf` line (`:4379`) only the qualifier changed, and the trailing comment is unchanged. No debug code. Only `encode_args_`'s five allocations are converted. The other `arena_alloc` callers keep taking the buffer and sending `contents` (`:1172`, `:1317`, `:6180`, `:6261`, `:10736`, `:10758`, the feedback and geometry includes, and others). That matches the catalog's cited lines (5377, 8210-8213, 7771), but not its wording "every caller sends `contents`". When the main thread records the state, it may want to say that only argument encoding was converted.

## Findings

1. **nit (docs, fix in the same commit): `docs/reference/frame-rate.md:274-280`, "Arena buffer ownership on allocation", is partly wrong after this diff.** The Fix says the `__strong` out-parameter is "matching every caller's strong local". After the diff, `encode_args_`'s callers (`nvn_mtl.m:8142,8151,8202,8210`) pass `NULL` and keep no local. The entry also does not say that `NvShader`'s `ab_buf` no longer owns its buffer and may dangle, which a future reader needs to know. Its Check does not name `t_arena_args`. `CLAUDE.md` requires correcting an entry that a change makes wrong. Suggested text:
   - **Cause:** keep, and add: "Every caller also read `buf.contents`, one more message per allocation."
   - **Fix:** "both declarations of `arena_alloc` use a `__strong` buffer out-parameter, matching the strong local of each caller that takes the buffer; a caller may pass `NULL`. `NvArena` caches its buffer's length and CPU address (`cpu`, its `contents`) when created; an arena keeps one shared-storage buffer for its life, so neither changes when it is reused. Allocation, reuse selection and idle trimming use the length. Argument encoding (`encode_args_`: push constants, the c0 / c2 driver segments, the border block and the argument block) passes `NULL` and writes through `g_cur_arena->cpu`, taking no reference and sending no message. `NvShader`'s `ab_buf` is `__unsafe_unretained`: the reuse test reads it only as an encoded-once flag, and it dangles once `arena_begin` trims the large arena that held the block, so nothing may message it outside the submission that encoded it. The arenas (`g_sub_arenas`, then `g_arenas`) still own every buffer, and fence-based reuse is unchanged."
   - **Found on:** add "The `cpu` pointer and the unretained `ab_buf` (refactor item C1) have not been measured on their own."
   - **Check:** add "`t_arena_args` checks on the GPU that the push, c0, c2 and border blocks and the argument block written through `cpu` are read back, in a new and a recycled arena, and checks same-pass reuse of an argument block."

2. **nit (test gap, optional): `t_arena_args.m` never fills an arena in the middle of `encode_args`.** Every block of one encode lands in the same arena, so the test cannot tell the per-allocation re-read of `g_cur_arena` (the code is right) from a version that caches `g_cur_arena->cpu` or `->gpu` once before the loop. It also would not notice the CPU and GPU sides coming from different arenas. A failure the test would miss: a later edit hoists `uint8_t *cpu = g_cur_arena->cpu` above the binding loop. When the push block takes an arena's last 256 bytes and c0 opens a new arena, c0 is written into the old arena past its end while the slot points into the new one. Adding `g_cur_arena->used = g_cur_arena->len - 256;` after `mtl_sub_begin()`'s first allocation in a third `compute_case` would put the push block in the old arena and c0, c2, border and the block in a new one. The GPU readback would then check every pairing.

3. **observation (no change needed): `ab_buf` can dangle** (described above, `nvn_mtl.m:4379`, `:5372`, `:7946`). Safe today because the only production reader is a nil test. Finding 1's doc text records it.
