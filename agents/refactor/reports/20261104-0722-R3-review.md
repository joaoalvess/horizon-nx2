# R3 review: the capture records the Switch 2 flag and the GOB order; `nvn_replay` answers `dm_sdk_ounce()`

Verdict: **approve with nits**

Diff: `/Volumes/Hangar/Games/overnight/patches/R3.patch`. The working tree's copies of its six files match the patch exactly (compared without the index lines). `dm/gfx/nvn/nvn_geometry.inc` was ignored, as the brief says. Read-only review: nothing was built or run.

## Findings

1. **Doc: the regression harness's list of ERROR causes misses the new one.** `docs/development.md:464` lists the reasons `regress.py replay` reports a capture as one the candidate cannot replay: the record layout changed, or the shader bindings changed. `scripts/regress.py:1295` runs `nvn_replay` without `--sdk-ounce`. So once R3 lands, every capture that `regress.py capture` recorded before R3 makes the candidate exit 2 at `nvn_replay.m:249`, and every game is an `ERROR`.
   - Refusing is the right behaviour: the alternative is to replay a Switch 2 frame in the wrong GOB order without saying so.
   - Failure scenario: the user runs `regress.py replay` after R3 and every game reports `ERROR`. Section :464 does not explain this, and does not say that one new capture per game fixes it.
   - Fix: add the cause to :464. The header comment at `regress.py:50` has the same gap, but it is a comment, so the rules leave it alone.

2. **Doc: one cause of exit status 2 is not documented.** `docs/development.md:507` lists the causes of exit status 2 but not the case where `--sdk-ounce` contradicts the capture (`nvn_replay.m:252`).
   - Failure scenario: `--sdk-ounce 0` on a new Pokopia capture stops with `[RED] nvn_replay: --sdk-ounce 0, but the capture was made with sdk_ounce 1`, which the doc does not mention.

3. **Doc wording.** `docs/development.md:509` reads "it refuses when a program's translated shaders take other bindings …, and a capture that does not say … unless `--sdk-ounce` gives it". It mixes "refuses when" with "refuses a capture". Suggested: "it refuses a capture whose programs' translated shaders take other bindings or inputs than at capture, and one that does not say whether the game's sdk was built for the Switch 2 unless `--sdk-ounce` gives it".

4. **Existing comments the change made incomplete.** Each of these is wrong or incomplete now:
   - `dm/gfx/tests/nvn_replay.m:5`: the usage line lacks `[--sdk-ounce 0|1]`.
   - `nvn_replay.m:8-9`: the list of exit-2 causes lacks the two new ones.
   - `dm/gfx/tests/t_capture_live.m:6`: the usage line lacks the optional `0|1`.
   - `t_capture_live.m:1-5`: the list of what the captured frame depends on lacks the CPU-written texture.
   - `dm/gfx/nvn/nvn_capture.h:23`: the `CAP_STAT` comment lists "(texture pool size, origin, depth mode)".

   The rules forbid new comments and edits to existing ones, so leaving them is defensible. The main thread decides whether to correct them.

5. **Test coverage has gaps (nit).** `check_t_capture_live`'s second run (`Makefile:146`) proves that the GOB order the live run used reaches the replay. The `ct` texture is enough for that: the pattern `i*37+11` differs between the 16-byte pieces the two orders swap (for example offsets 32 and 64 inside a GOB). Three things are not exercised:
   - Nothing checks that the live run really used order 1. `t_capture_live.m:40` derives `nvn_gob_switch2` from `dm_sdk_ounce()`. If the weak default (`hle_nvn.c:184`) ever won the link, both runs would silently be Switch 1 runs and the check would still pass. It does not win today (see "Link" below).
   - The replay's `dm_sdk_ounce()` answer is not covered. It decides the NVN2 c0 dispatch dimensions (`nvn_mtl.m:8173`, `:10897`), and the test has no dispatch.
   - The two refuse paths (`nvn_replay.m:249`, `:252`) never run.

   One `if (argc > 2 && nvn_gob_switch2 != 1) FAIL` after `:40` would close the first gap.

6. **Optional: no reference entry.** The capture and replay mechanisms found so far each got an entry in `docs/reference/nvn-objects.md`, with a symptom-index line:
   - replay serials (:144-146);
   - gone pools (:153);
   - interface hashes (:172-174).

   R3's symptom fits that pattern: a Switch 2 replay that differs from the live frame in 10^5-10^6 pixels wherever CPU-written textures are sampled. `CLAUDE.md`, "Where a new finding goes", suggests an entry, with `docs_symptoms.py` run afterwards. This is not required for the code.

Trivial: `--sdk-ounce` goes through `atoi` (`nvn_replay.m:251-252`), so any value other than a number reads as 0. The other options behave the same way.

## What holds

- **Capture.** `cap_head` (`nvn_capture.inc:340`) appends `gob_switch2` and `sdk_ounce` to the `CAP_STAT` text.
  - The line buffer is 2,048 bytes, so nothing is truncated.
  - `head_get` matches whole keys followed by a tab (`nvn_replay.m:106-113`), so neither key can match another.
  - The values are the live ones. `nvn_gob_switch2` was set at `nvnDeviceInitialize` (`hle_nvn.c:127`). `dm_sdk_ounce()` is the loader's strong definition in `dmhost` (`loader.c:151`): it is cached after device init, so it adds no new log line.
  - Both symbols are visible in the include: `nvn_mtl.m` includes `nvn_deswizzle.h` and `dm.h`.
- **Replay parse.**
  - A capture without `CAP_STAT` (`stat = ""`, `sn = 0`) or without the keys gives -1 and stops with exit 2 unless `--sdk-ounce` is given.
  - With the keys present, `--sdk-ounce` must agree with `sdk_ounce`.
  - `ounce` and `gob` are kept apart, which is faithful to the live state; a live run has them equal after device init. For an old capture, `--sdk-ounce` sets both, which is correct.
  - Both globals are set before `apply_env` and `mtl_init` (`nvn_replay.m:253-256`), and nothing before that reads them.
  - The replay never calls `nvnDeviceInitialize`, which would reassign `nvn_gob_switch2`.
  - Replayers from before R3 ignore the new keys, so new captures replay on older trees exactly as before.
- **`--repeat`.** The flag is passed to each child (`nvn_replay.m:214`). `args[16]` holds at most 13 entries. The parent does not parse the capture, and each child checks again.
- **Other SDK-derived state.** The replay layer reads two SDK-derived values, `dm_sdk_ounce()` (`nvn_mtl.m:8173`, `:10897`) and `nvn_gob_switch2` (`nvn_deswizzle.c:14`, `:61`; `nvn_deswizzle_gpu.m:39`, `:56`, `:78`). Both are now recorded. Nothing else SDK-derived reaches the replay:
  - `dm_sdk_major`, `dm_sdk_nvn2_item` and `dm_glslc_gpu_code` feed only the guest's answers (`nvn_api`, `nvnDeviceGetInteger`). `hle_nv.c` is not linked into the replay.
  - `guest_ticks` (`hle_os.c`) is host-only, and the replay layer's timestamps do not depend on the SDK.
  - The device-level state `hle_nvn.c` sets through `mtl_set_*` (texture pool size, origin, queue origin, depth mode) was already in `CAP_STAT`. `mtl_set_frame` is set per frame.
  - `nvn_tex.c` layouts do not depend on the SDK, and `tex_t`, including its layout `L`, is captured whole.
  - The NVN2 shader paths are chosen from each shader's control section, which is in the program keys and the libraries.
- **Link.** `sdk_ounce.c` is added only to the `nvn_replay` and `t_capture_live` rules (`Makefile:134-135`, `:142-143`), both as a prerequisite and on the command line.
  - Both targets include `hle_nvn.c` in their own translation unit, so the strong definition lives in a separate one, where it cannot collide with the weak one. Under ld64 and ThinLTO, a strong definition is the prevailing copy, and a non-prevailing weak (non-ODR) copy is dropped rather than made available_externally, so it is never inlined. The host already relies on the same mechanism (`loader.c` against `hle_nvn.c`).
  - Every other test keeps the weak 0: `t_nvn`'s API expectations are unchanged, and `t_deswz_gpu`, `t_tex` and `t_sparse_tile` set `nvn_gob_switch2` themselves.
  - Nothing else defines `dm_sdk_ounce` or `g_sdk_ounce` (`t_host_stubs.c` does not).
  - Taking `sdk_ounce.c` out of a rule fails at link time (`g_sdk_ounce` undefined).
  - It is not on the run list (the name is not `t_*`), and `dm/gfx/tests/.gitignore` does not ignore it.
  - `test_gfx_tests_makefile.py`'s rule regexes still match.
  - The host (`dm/host/Makefile:22-23`: its wildcard leaves out `tests/`) and the iOS build (`gen_build.py` takes the host's `make -n`) do not get the file.
  - `lint_c.py` picks it up through `t_capture_live`'s command, and the configured checks have nothing to flag in it.
- **`t_capture_live`.**
  - `ct` is a 16x16 RGBA8 block-linear texture at pool + 0x3c000. That is inside the 256 KiB pool and clear of the 0x30000, 0x34000 and 0x38000 uses.
  - It is marked CPU-written before its bytes are written. `mtl_tex_cpu_written` only marks the texture (`nvn_mtl.m:2630-2641`), so frame 2 uploads the pattern.
  - `ct` is not a Metal-only texture, so the capture does not restore it from a readback. The replay therefore deswizzles it from the pool, which makes the second check sensitive to the GOB order.
- **Scope.** No comments were added and no debug code was left behind. Nothing outside the item changed. The doc text otherwise matches the code: the log string is the one at `loader.c:159`, the `--sdk-ounce 1` / `0` behaviour is as described, and so is the description of `check_t_capture_live`.
