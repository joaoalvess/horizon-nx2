## Findings

### 1. High: the move check accepts dropping a function-local `static` as a linkage edit
`dm/tools/mtlsplit/movecheck.py:68-82` (`static_variants`, first loop at 71-72) builds a variant of the removed line for every `static` in its code, not only the one that starts a declaration. Line 128-130 accepts any of them. The docstring (line 8) and the plan (linkage = "the static of a declaration starting on it") are narrower than this.
- Scenario: 53 top-level lines hold a second `static` after a brace, most of them one-line functions with a local static, e.g. prof's `cp_on` (`nvn_mtl.m:141`), `ws_on` (`:178`) and dev's `tbdr_on` (`:3689`, `static int v = -1`). Suppose a hand fix of the prof move writes `static int ws_on(void) { int v = -1; ... }` instead of `int ws_on(void) { static int v = -1; ... }`. The move check passes, because both variants are accepted. `getenv` and `MLOG` now run on every call; for `tbdr_on`, "TBDR optimizations off by default" is printed on every draw. The command stream is the same, so the digest passes too. Probe: an inner-static drop returns `(True, [])`.
- Fix: accept only the removal of the leading `static` of a statement or declaration that starts on the line, before its declarator (what `move.py`'s `linkage` / `strip_static` does), and only for names the header declares.

### 2. High: any `#` line of `nvn_mtl.m` may be added anywhere in a module, any number of times
`movecheck.py:175`: `if s.startswith('#') and t in self.unit_lines: return True`. `unit_lines` holds every directive of the unit (`main`, line 207): `#if 0` (`nvn_mtl.m:3600`), `#endif`, `#else`, `#ifdef NVN_RT_RANGE_TEST`, `#if TARGET_OS_IPHONE` and every `#define`.
- Scenario: a move commit puts `#if 0` and `#endif` around statements of a moved function, e.g. the `g_res_dirty = 1;` in `res_add_at`. Both lines count as "generated", so the check passes, and the Mac build silently drops the code. With `#ifdef NVN_RT_RANGE_TEST` instead, the dropped code is a whole function. Probe 2 confirmed this.
- Fix: accept generated directive lines only as the prelude `move.py` writes: the unit's lines before its `#pragma clang attribute push`, then the push and the `#include`s after it, all at the top of the `.m` before the first moved line, and the pop as its last line. Check them as one block equal to what `Move.prelude` produces.

### 3. Medium: what goes into the header is not checked, and the generated-declaration rule depends on patch order
- `movecheck.py:104-108` puts the `.m` and `.h` into one pool. A moved line counts wherever it lands, so a `static int g_x;` line, or a function with a local static, can go into the header verbatim. Every module that includes the header then gets its own copy of the state. Probe 4 passes.
- `movecheck.py:176-180` accepts as a "generated declaration" any `;`-terminated header line whose words come from the moved lines. That includes `static int k;` (a new per-file definition) and `__attribute__((const)) int f(int);` (probe 5). `where` (line 108) is keyed by text and keeps the first file the line was added to. With `git show` order (`mtl_x.h` before `mtl_x.m`, the `--rev` path), an extra `static int k;` in the header passes. With the `.m` first, the same patch fails (probe 13).
- Scenario: a move commit declares `static id<MTL4RenderCommandEncoder> g_enc;` in `mtl_sink.h` instead of `extern __attribute__((visibility("hidden"))) id<...> g_enc;`. Every later module compiles against its own nil `g_enc`, and the move check passes under `--rev`.
- Fix: keep one pool per path. In the header, accept moved lines only from items `Move.header_ok` would accept: types, macros, and `static inline` functions with no local static. Then regenerate the expected declarations from the removed lines, which the check holds, and compare them exactly. Refuse `static`, initializers and any attribute other than the hidden visibility.

### 4. Medium: order is not checked
`movecheck.py:99-124` compares multisets, as the plan's text says. But `move.py` writes each module file's moved lines in translation-unit order (`tu_order`, header items hoisted into the `.h`), so a stricter check costs nothing.
- Scenario: swapping two lines of a moved function body (`k = 1;` and `k++;`, probe 3), or moving a `#define` below its users, passes the move check.
- Fix: for each module file, require the moved lines, with generated lines removed, to be a subsequence of the removed lines in TU order. Each `.inc` is read at its `#include`, the walk `tu_order` already does.

### 5. Medium: the call check compares callee sets, not call sites
`dm/tools/mtlsplit/callcheck.py:102`: `added = sorted(set(new[f]) - set(base[f]))`. The counts are collected (line 51) but never compared.
- Scenario: base `draw_` already has one `bl rt_sub` on a cold site. After a move, `rt_sub` (an `inline` row) stops being inlined at its three per-draw sites. The callee set is unchanged, so the check reports "same calls" and exits 0 (probe 8: 1 call becomes 4, no RED).
- Fix: flag `new[f][c] > base[f][c]` with the same verdicts, and print the counts.

### 6. Medium: a checked function that disappears passes, and the plan's ThinLTO `draw` case is only half handled
- `callcheck.py:100-101`: a function present in only one binary gets the line "only in the … binary (inlined in the other)", and the check exits 0. Scenario: after a move ThinLTO inlines `rp_end` or `encode_args_` into its caller. Its calls are no longer checked anywhere, and the check passes (probe 9). `checked` (line 65) also silently drops `--function` names that neither binary has, and can then report "0 functions, no new call".

### 11. Low: the header-prelude rule is sound today, under conditions the tool does not check
`move.py:466-484` copies a header included after the push (`../../host/front.h` `:1706`, `nvn_pso_skey.h`, `nvn_geometry.h`, `nvn_feedback.h` `:4389-4391`) only when the module names one of the names `declared_names` (`move.py:61-83`) finds in it. Those four headers hold only C declarations, `static const` data and `static` / `static inline` functions. They have no mutable state and no `#define`, `#undef`, `#pragma` other than `once`, or ObjC declarations. So skipping one can only cause a compile error, and copying one cannot split state. The rule would become unsound if one of them gained a macro, `#undef` or `#pragma` that acts on code that does not name it, or an ObjC selector declared elsewhere with another signature. - it does not follow nested includes (`nvn_pso_skey.h` includes `nvn_obj.h` and `nvn_pso_ds.h`).

The prelude also reads only `nvn_mtl.m`'s includes. `nvn_capture.inc:9-10` (`nvn_capture.h`, `<crt_externs.h>`) are mapped to the facade and stay behind, so the capture move will not compile as produced.
- Fix: have the tool refuse an after-push header that holds any of those constructs, and include the `.inc` file's own includes in the module that takes the file.

## N1 check (2026-11-04 20:52)

Verdict: **approve with nits**. `absorb` (`callcheck.py:157-170`, called at `:215`) fixes N1, and on the prof data it hides nothing. It can hide a real new call in narrow cases, and two of them are cheap to close. Unit tests: 30 pass. Probes: `/private/tmp/claude-501/-Users-joaoalves-Developer-switch/fd5fcbce-ad70-4407-952b-560d6e7b6b20/scratchpad/probe/n1.py`, which calls `compare` with the test's rows.

**Prof.** Only `rp_begin_ex` is absorbed. The objc stubs are undefined symbols, so they cannot be absorbed. The 6 defects left (`rt_sub`, `lc_same`, `fputc`, `funlockfile`, `fwrite`, `objc_release` +1) are the same ones my own fold of `rp_begin_ex`'s base body left in round 2. None of that body's callees is an `inline` row (`callcheck_allow.tsv:6-31`), so the fixes below do not change the prof result.

**Where `absorb` hides a real call:**
- **Medium. The cascade through a phantom drop (`:160-170`).** `absorb` adds `drop × m` for every callee in the body, whether or not the new binary calls it more often. A body callee `g` that never rose then shows up as "fewer". The loop absorbs it in turn, and `g`'s body can explain a real new call. Probe c: base `draw_` {h:2}, `h`→{g}, `g`→{y}; new `draw_` {h:1, y:1}. The result is `bad=0`, "same calls". Fix: add at most the rise the new binary shows, `min(drop*m, max(0, n[k]-b[k]))`. This stops phantom drops, and so the cascade. It cannot change the "more" verdicts of the first fold.
- **Medium. Inline rows (`:215-225`).** A rise in a must-stay-inline callee can be explained away. Probe b′: the move un-inlines `rt_sub` at one site, while `h`, whose base body calls `rt_sub`, is inlined at one more site. The result is `bad=0`. This is exactly the regression the inline rows exist to catch. Fix: never let a fold explain a rise of a callee whose verdict is `inline`. Keep it `[RED]` and add "possibly through inlined h", for a reader to settle in the disassembly.
- **Low. Ambiguity that counts alone cannot settle.** Probe a: `h`'s count falls because two call sites merged (tail merge or branch folding), not because of inlining, and the move adds a real call to `x`, which `h`'s body also calls. Counts cannot tell this apart from inlining. Mitigation: the report lists the rises each fold explained (for example "x 0 -> 1 explained by h"), not "same calls", so they can be checked.
