## What the diff does

1. `cp_on`'s once-computed `DM_NVN_CPUPROF` flag moves from `static _Thread_local int` to `static _Atomic int`. It is read and written with `memory_order_relaxed`, still lazily, and the value is the same (`e && atoi(e)`).
2. Each profiled call site now does a plain load (`adrp; ldr w8; tbnz; cbz`) instead of a TLV access (`adrp; add; ldr x8; blr x8` into dyld's `tlv_get_addr`, then `ldr`). That is about 12 fewer instructions per check.
3. The counters `g_cp_wall/cpu/calls/last` and `g_cp_geo_*` stay `_Thread_local`. `cp_begin`, `cp_end` and `cp_report` are unchanged.

## The claim, and why the flag was thread-local

- **Origin.** The flag came with the counters in upstream `2c31212f` ("Integrate NieR geometry optimizations…"), declared `_Thread_local` like them. That made the lazy initialisation race-free.
- **Threads.** `cp_on` runs on the submit thread, on the encode thread (`rec_thread`, `nvn_rec.h:209`) and in `pp_bg_queue` blocks (the geometry paths).
- **Nothing needs a per-thread value.** The flag comes from one process-wide environment variable. No code sets `DM_NVN_CPUPROF`: the only other hit is `dm/tools/tests/test_player_env.py:15`, which drops it from the player's environment. No gfx test uses it.
- **The claim holds at HEAD (-O2 ThinLTO).** In the DK `head-6757b33f` host, `_cp_on.on` is in `__DATA,__thread_vars`. There are 23 TLV accesses to it (`adrp/add #0x540/ldr/blr`) in 16 functions: `draw`, `draw_`, `encode_args`, `pso_get`, `rp_begin_ex`, `rp_end`, `tex_mtl`, `geo_draw`, `geo_capture_one`, `geo_mesh_encode`, `dispatch`, `defer_replay`, `defer_fallback`, `mtl_sub_index`, `mtl_stats` and `cp_on`.
- **After the change**, in the `cand-C7` DK host:
  - `_cp_on.on` is gone from `__thread_vars`, and the `g_cp_*` counters are still there;
  - `draw` begins `adrp x21; ldr w8, [x21, #0xfc4]; tbnz; cbz`, with no `blr`.
- **Form chosen.** The brief allowed two forms; this one uses relaxed C11 atomics. The other, a plain value set in `mtl_init` like `g_vbuf_cache` / `g_res_check_on`, was rejected:
  - `mtl_init` has six internal callers (`if (g_dev) return;`) and many test entry points. Proving that it happens before every first `cp_on` on every thread would take more reasoning than the item is worth.
  - The relaxed atomic is self-contained, has no data race (threads racing the first call compute the same value), and costs the same on arm64: a plain `ldr`.
- **Per-check cost** (`scratchpad/c7/micro.c`, clang -O2, `noinline`, `ri_instructions` over 10^8 calls):
  - thread-local: 27.00 instructions a call;
  - relaxed atomic: 15.00;
  - loop plus empty function: 4.00;
  - so the change saves 12 instructions per check.
