# C6 review: `__unsafe_unretained` locals in the per-draw path

Diff: `/Volumes/Hangar/Games/overnight/patches/C6.patch` (same as the working tree's `dm/gfx/nvn/nvn_mtl.m` diff) on HEAD `019a133f`. Line numbers are the working tree's.

**Verdict: approve with nits**

The five changes are safe. Every object outlives every use of its local on every path that has a program with a serial. The nits: the `draw_` change (:10445) saves no retain / release; there are strong locals of the same kind on the same paths; one doc statement is wrong. Scope is clean: five declarations, no comments, no reformatting, `en` (:10536) stays strong.

## Owners (shared by the proofs)

- **Shaders.**
  - An `NvShader` in a host program's `sh[]` comes from:
    - `shader_get` (:4712);
    - `shader_get_layer` (:4722);
    - `shader_prefetch_rest` (:8544);
    - `warm_claim` (:10784-10795);
    - the geometry kernels, through `shader_get` (`nvn_geometry.inc:339`, `:582-583`);
    - `builtin_get` (:4759).
  - All of these sit in `g_shcache` or `g_builtin` for good:
    - no code in `dm/gfx/nvn` removes, replaces or clears an entry;
    - `:8544` stores only keys that were absent when it walked the commands;
    - `warm_claim` stores only absent keys.
  - `sh[]` is written only on a program under construction:
    - `prog_get` (:4780, :4792);
    - `prog_fold_gs` (:4734);
    - `bind_stages` (:5649);
    - `geo_lean_mesh` / `geo_raster` (`nvn_geometry.inc:458`, `:729`).
  - So a live program's `sh[]` never changes, and its shaders are immortal in the host.
- **Programs.**
  - The owners of an `NvProg` from `prog_get`:
    - `g_by_serial`, filled by `serial_put` (:4796) or `prog_serial_put` (:5651);
    - `prog_get`'s strong static `lpr` (:4766; `objc_storeStrong` in the built `_prog_get`);
    - from `geo_prep` on, the strong field `geo_job.pr` of the static `g_geo_run` (`nvn_geometry.inc:475`, `:536`).
  - Every drop of a table entry queues the object in `g_deferred` before the table's `CFRelease`:
    - the drops are `serial_put` / `serial_del` (:1831-1832) and `prog_serial_del` (:1834);
    - the queue holds it through the strong `NvDeferredRelease.object` (:278), with `fence = g_fence + 1` (:289).
  - Fences and drains:
    - `g_fence` is `_Atomic` (:129) and advances only at `mtl_sub_commit` (:1610). Its only caller is `nvnQueueSubmitCommands` (`hle_nvn.c:1292`), after the op loop.
    - `defer_drain` (:300) runs only in `mtl_sub_begin` (:814) and in the submission's completion handler (:1633), and frees only entries with `fence <= g_done`.
    - `mdi_wait` (:10098) and `sub_cut` (:11540) commit command buffers without advancing `g_fence` or draining, and their handlers do not drain.
  - So a program dropped during a submission survives until that submission completes. This includes a `mtl_prog_release` on a game thread: its `g_fence` read names the submission being built or a later one.

## Findings

**N1 (nit): `nvn_mtl.m:10445` saves no retain / release.**

- Clang ignores an ownership qualifier on a function's return type. The toolchain's clang carries the diagnostic "ARC %select{...__unsafe_unretained...}0 lifetime qualifier on return type is ignored", which is in `-Wignored-qualifiers`, outside `-Wall`.
- So `static __unsafe_unretained NvProg *prog_get` (:4764) is an ordinary +0 return. The built `dm/host/dmhost` (10:51) shows it:
  - `_prog_get` calls `objc_retain` on its result in the cached path and in the lookup path (`+0xd0`), then tail-calls `objc_autoreleaseReturnValue` (`+0x760`).
  - In `_draw_`, the :10445 site is `mov x29, x29; bl objc_unsafeClaimAutoreleasedReturnValue`, which releases at once.
- Before C6, the strong local paid the same retain in the callee, with its release at the end of the block. After C6, it pays the same retain, with the release right after the call. That is still one pair, only earlier. The same holds for every `prog_get` caller, for example `pr` at :10458 (claim, then release).
- The pair could go away only if `_prog_get` were inlined; it is not.
- The change is harmless. Only the catalog's saving estimate should not count it. The pairs saved come from the four `sh[]` loads:
  - `image_prepare`: one per stage present;
  - `fb_prepare`;
  - `draw_color_writes`;
  - `dispatch`'s `cs`.

**N2 (nit): strong locals of the same kind left on the same paths.**

- On every draw:
  - `udc_note_draw` :5604, `NvShader *fs = pr ? pr->sh[1] : nil;`, called at :10698. This is the same pattern as :10410, and its sibling locals there are already `__unsafe_unretained`.
  - `zskip_can_draw` :9551, `NvShader *fs = nil; ... fs = pr->sh[st]`, when `zskip_on()` (on by default with TBDR).
  - `draw_gs_check` :4742, `NvShader *g = pr->sh[2]`. It is nil for most programs, so cheap.
- On every dispatch:
  - `dispatch` :10854, `id<MTLComputePipelineState> ps = hm_get_id(&g_cps, &k)`. It cannot simply be made `__unsafe_unretained`: the miss path assigns a new +1 pipeline before `hm_put_id`.
  - `ce` :10890 is an encoder, like `en`.
- On every geometry draw:
  - `nvn_geometry.inc:538` (`vs`, `base`);
  - `:585` (`gs`, `reader`);
  - `:588` (`lean`);
  - `:727` (`pr`, `raster`);
  - `:773` (`pr = prog_get(...)`);
  - `:313`, `:334`, `:341`, `:384`, `:387`, `:408`.
- On transform feedback draws: `nvn_feedback.inc:59`.
- Cold or diagnostic:

  - :9664 (`DM_NVN_KEYDUMP`);
  - :9586 (merged pass phase 2);
  - :9452 (`fuse_try`, per pass);
  - `rt_range_check.inc:15`.

**N3 (out of scope, existing): `prog_get` on a program with serial 0 returns an object nobody owns.**

- A program can have serial 0: `nvnProgramInitialize` sets it (`hle_nvn.c:631`), and only `SetShaders` gives a serial.
- For such a program, `prog_get` builds `o`, puts it in no table (:4796) and does not set `lpr`. Its only reference is the autoreleased return.
- After C6, `objc_unsafeClaimAutoreleasedReturnValue` frees it at once, so :10446 `geometry_program->sh[2]` reads freed memory. Before C6, the strong local kept it alive to the end of the block.
- The existing `__unsafe_unretained pr` at :10458 already frees it the same way. `image_prepare(pr)` at :10459 then reads freed memory on that path.
- So C6 adds an earlier bad read on a path that already had one, and creates no new failing path. It is reached only by a draw with a program that never got shaders, which has not been seen.

**N4 (doc): `agents/architecture/lifetimes.md` section 1 is wrong about lookups.**

- It says the lookups "return `__unsafe_unretained`" and lists `hm_get_id`, `serial_get`, `tex_get`, `prog_get` and `pso_get`.
- For `prog_get`, the qualifier is ignored (N1): the function returns a retained, autoreleased +0 value. The other four were not checked; they are declared the same way.
- The lifetime conclusion still holds. The cost model in that row does not.

No race, lock-order change, Metal-visible change, guest-visible change or debug leftover found.
