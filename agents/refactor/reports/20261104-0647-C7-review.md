## What was checked

### Semantics: same value on every thread for every value of `DM_NVN_CPUPROF`

- Old: `static _Thread_local int on = -1; if (on < 0) { e = getenv(...); on = e && atoi(e); } return on;`
- New: `static _Atomic int on = -1;`, relaxed load into `v`. If `v < 0`: the same `e && atoi(e)`, a relaxed store, then `return v`.
- `e && atoi(e)` is always 0 or 1, so the sentinel `-1` is never stored again in either version. Values:
  - unset, `""`, `"0"`, `"x"`, `"0x1"`: 0;
  - `"1"`, `"2"`, `"-1"`, `" 1"`, `"1x"`: 1;
  - the same in both versions.
- While the environment does not change, the old version computes the same value once per thread and the new one once per process (more often only if threads race the first call), so every thread gets the same value. `cp_begin` (`:142-145`), `cp_end` (`:146-151`, keyed on `start.wall`, not on `cp_on`), `cp_report` (`:152-164`) and the `g_cp_*` counters (still `_Thread_local`, `:139-140`) are unchanged.
- `<stdatomic.h>` is included at `nvn_mtl.m:67`, before line 141. `_Atomic` was already in use in this file (`g_fence`, `:127`).
- Every file that `#include`s `nvn_mtl.m` is a `.m` (about 75 files in `dm/gfx/tests`, all C/ObjC, none ObjC++). Each binary has one copy, so there is one flag per process, as before there was one per thread.
- Binary check (`cand-C7` DK `dmhost`, `otool -tV -p _cp_on`): `adrp x19; ldr w0, [x19, #0xfc4]; tbnz w0, #31` on the fast path; `getenv`, `atoi`, `cset`, then `str w0, [x19, #0xfc4]` on the slow path.
  - `nm -m`: in `head-6757b33f`, `_cp_on.on` is in `__DATA,__thread_vars`. In `cand-C7` it is gone from there, and `_g_cp_wall` / `_g_cp_geo_safe` are still in `__thread_vars`.

### Memory order

Relaxed is correct and sufficient:
- the flag publishes no other memory: the counters it gates are thread-local, and the clocks are read locally;
- atomicity removes the data race, and per-object coherence means a thread that has seen 0 or 1 never sees -1 again;
- racing first callers store the same value. Only if a `DM_CTL` `setenv` landed inside that race could one thread see a single 0↔1 flip. That is harmless, since `cp_end` pairs on the stamp and not on `cp_on`;
- on arm64, relaxed gives a plain `ldr` / `str` (confirmed above); acquire or seq_cst would give `ldar` / `stlr` for no benefit;
- a plain non-atomic `static int` (the style of `ws_on` / `ubc_on`) would be a formal data race. `t_thermal_tsan` (`dm/gfx/tests/Makefile:99`) compiles `nvn_mtl.m` with `-fsanitize=thread`; the atomic keeps it clean.
- C7 also cuts the number of `getenv` calls from one per thread that touches the profiler to about one per process. That reduces exposure to a `getenv` racing `DM_CTL`'s `setenv`.

### Placement / false sharing

- The flag is now at `0x100360fc4`, inside `__MergedGlobals` in `__DATA,__data`. That 128-byte line also holds globals written per draw and per present (`draw_`, `rp_end`, `mtl_exec`, `up_alloc`, `present_enqueue`, `h_nvnQueuePresentTexture`, `h_nvnWindowAcquireTexture`, `tex_mtl`).
- The flag itself is never written after initialisation, and every thread that reads it already reads and writes that line in the same functions (`draw_`, `tex_mtl`). C7 adds no new sharing.
