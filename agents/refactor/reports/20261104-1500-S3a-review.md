# S3a review: command-stream digest (item mode)

Reviewed: the uncommitted diff of `dm/gfx/nvn/nvn_rec.h`, `dm/gfx/tests/Makefile`, `dm/gfx/tests/nvn_replay.m`, `docs/development.md`, and the new `dm/gfx/tests/nvn_rec_digest.inc`, `dm/gfx/tests/t_rec_digest.m`, against the code at HEAD `32913850` plus that tree. Read-only; nothing built or run.

**Verdict: approve with nits.** The tap, the per-op table, the naming and the dispatch shim are correct, and the shim cannot deadlock. One finding (M1) should be fixed, or at least written down, before S3a's baselines are taken: the replayer reads and writes the live run's pipeline state on disk. Because of that, a `--repeat` child, or a baseline, can give a different digest from the next one without any change to the code.

## M1: cross-process pipeline state flips the digest between fresh replays (medium)

- `nvn_replay.m:121-131` (`apply_env`) applies every `DM_*` setting of the live run. `nvn_capture.inc:336` records all of them, `DM_SAVE` included. So the replay uses the live run's `pso_user.tsv` (`nvn_mtl.m:4460-4464`) and its `pso_archive/` (6584).
- **What a replay writes:**
  - Every pipeline a draw built is appended to `pso_user.tsv` and flushed at once (`pso_user_record`, 7261 → 4487).
  - Compiled bases reach the archive through `arch_note_new`'s 10 s `dispatch_after` (6782 → 6671), which the shim does not cover.
  - Whenever `prebuilt.tsv`'s stamp (chain, depth mode, pair list: 7043) does not match, `warm_finish` → `pso_prebuild_bg` → `pso_prebuild(..., wait 0)` runs workers on `dispatch_group_async` and finishes in `dispatch_group_notify` (7111, 7137). The shim does not cover those either.
- **What the next replay reads:** its prewarm (inline under `--digest`, 7512, user list at 7493, claimed by `warm_claim` 817) and its archive (`pso4_init`). These decide at 7225/7228 whether a draw takes its own pipeline or the hybrid pulling stand-in plus its layout block.
- **Scenario:**
  - Setup: a capture whose frame draws a pipeline key that `pso_user.tsv` lacks, at least twice. This is the usual case when the boot is stopped soon after a capture taken just after a scene change.
  - Child 1: the first draw takes the stand-in, and 7233 returns before 7261. The demanded build runs inline. The second draw takes that pipeline (`pso_pend_try` = 2) and records the key (7261).
  - Child 2: the prewarm builds the key from the user list, so the first draw hits `g_pso`. There is no pulling pipeline and no layout-block `T_ADDR`.
  - Result: `--repeat 2 --digest` prints `[RED] command digest: 2 distinct digests` and exits 1. A `--digest-expect` baseline taken on the first run fails every later run of the same tree.
  - Same failure, second route: after a chain change (stage U, S3b), the background prebuild races the frame's `pso_build_ex(..., 0)` lookups (6756: "another thread is taking or building it: no wait").
- **Effect:**
  - The pixels do not notice: pulling and own pipelines are bit-identical by design. So the only symptom is a false "commands changed" on a pure move. It never misses a real change.
  - The replayer also changes the live run's folders. That was already true for pixel replays.
- **Fix, either of:**
  - Under `--digest`, let the parent snapshot `pso_user.tsv` and `pso_archive/` (a `cp -c` clone). Give every child `DM_PSO_USER` and `DM_PSO_ARCHIVE` on a fresh clone of that snapshot, and set `DM_PSO_PREBUILD=0` after `apply_env`.
  - Or, at least, document in the S3a docs and `captures.md` that a capture is replayed once to settle before its baseline.
- **Related doc overclaim** (`docs/development.md:509`):
  - "what the replay layer would hand to a background queue ... runs at once" is too broad: the prebuild and the archive flush stay on background queues.
  - The list names "the shader prefetch" (`mtl_prog_prefetch`, 10817). Only `hle_nvn.c:717` (nvnProgramSetShaders) calls it, and the replayer never does.
  - The list leaves out the pipeline prewarm (7512), which the replayer does reach (`check_programs` → `prog_get` → `shmap_load` → `warm_start`). The whole prewarm now runs synchronously inside `check_programs`.
  - It also leaves out the hybrid pulling bases (6943) and demanded builds (`pso_pend_demand`); "speculative pipeline builds" covers only `pso_pend_kick`.

## Claims checked

1. **Host unchanged: holds.**
   - `NVN_REC_TAP` is defined only at `nvn_replay.m:14` and `t_rec_digest.m:1`, and no Makefile passes it.
   - `nvn_rec.h:77-79` and `190-192` compile to nothing otherwise.
2. **Options: hold.**
   - `--digest`, `--digest-dump`, `--digest-expect` and the internal `--digest-file` are parsed at `nvn_replay.m:209-212`.
   - The recorder is forced after `apply_env` (279). The tap is reset per replay (355) and finalized before the readback (391), and the result is printed and checked at 441-446.
   - The parent passes the options to its children (230-232). It exits 1 on more than one digest, and on a missing child line (238-244).
3. **Inline dispatch: no deadlock.**
   - Every site the shim reaches releases its lock before it dispatches: `pso_pend_start` 6861/6862, `hybrid_get` 6942/6943, `sm_amp_get` 7182/7184, `geo_mesh_pso` `nvn_geometry.inc:414/423`, and `warm_start` 7512, which holds none.
   - No block waits for its caller, targets the main queue, or re-enters a `dispatch_once` that is still running (`pso4_init`, `pp_bg_queue`).
   - The blocks read only their captured descriptors (`pso_build_ex` and `pso_desc4` read no `S` or `g_pass`). So running them inside `pso_predict_rest_` before `S` is restored (8604) is safe.
   - `pso_build_ex`'s wait (6757) can only wait for another thread's job, never for itself.
   - `hle_nvn.c` has no `dispatch_async`, and 6593 is iOS-only.
4. **Liskov: holds.**
   - The tap runs before `rec_exec` (`nvn_rec.h:190-193`).
   - The render-pass descriptor is copied before its attachments are read (`inc:122`), so the recorded one is never filled in.
   - The associations retain only an `NSNumber`.
   - The buffer table is weak, and a hit is checked against `gpuAddress`.
   - Residency is read under `g_res_mu`, and no holder of that lock waits for the encode thread.
5. **Layouts: hold.**
   - There are 52 ops and 52 layouts. Every spec letter matches the stand-in's `a[]` order (`nvn_rec.h:113-177`, `252-337`).
   - `RO_COMMIT`'s unset `a[1]` is skipped by `-`, `RO_COMMIT_REAL`'s `a[2]` is not read, and `m` takes its count from `a[4]`.
   - An unknown or unlisted op stops the replay (`inc:134`).
6. **Naming: holds.** The epoch changes at every `rdg_reset`, and an association dies with its object.
