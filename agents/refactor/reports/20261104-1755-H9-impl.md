## Verdict

H9 impl: ready. The item's claim holds. The pause loop of SetThreadActivity can read, wait on and signal through a freed `thr_t`. The fix pins the target for the length of the loop, as Horizon's SVC holds a reference to the thread it looked up.

## Cause, from the code

The only code that frees a `thr_t` is `thr_free` (`hle_thread.c:386`). It unlinks the thread from `g_all`, clears `hand[]` / `start_by` entries that point at it, waits for `cv_pend` to reach 0, destroys `cv` and `pcv`, then frees. It has two callers, both under `G`:
- `thread_exit` (`:404`) when `closed` is set (ExitThread, SVC 0x0A);
- CloseHandle (`:1217`) when `exited` is set.

`dm_guest_thread_join` reaches the same CloseHandle through the SDK's DestroyThread. The test fixtures' `gthr_join` unlinks static objects by hand and frees nothing.

A closed handle can coexist with a pause in progress. SetThreadActivity looks up the handle under `G` (HEAD `:1039`), so the handle is open at that moment. The pause loop then releases `G` twice in each pass, and CloseHandle needs nothing but `G`:
1. around `pthread_kill(t->pt, SIGUSR2)` (HEAD `:1048`). `t->pt` is read after the unlock, then `paused` / `exited` after the relock;
2. inside `pthread_cond_timedwait(&t->pcv, &G, …)` (HEAD `:1051`), 100 µs. After it come the `t->handle` read for the `[RED]` line and the loop test.

The target can also exit during the pause. `on_pause_sig` stops a thread only in module code, so a thread in host code keeps running. `thr_svc_enter` marks it paused but lets the SVC run, ExitThread included; only `thr_svc_leave` blocks, and ExitThread never leaves.

Interleaving A, freed by `thread_exit`. Requester R, target T, closer C:
1. R: SetThreadActivity(h, 1). Under `G`: `h_get` → T, `pause_req` = 1, `svc_state |= 2` (bit 0 clear), loop.
2. R: `pthread_mutex_unlock(&G)`.
3. C: CloseHandle(h). Under `G`: the slot is freed, `T->closed` = 1, T has not exited, so no free.
4. T, in host code: SVC 0x0A. `thr_svc_enter` sets `paused`, then `thread_exit` under `G`: `exited` = 1, `closed` → `thr_free(T)` → `pthread_cond_destroy(&T->pcv)`, `free(T)`.
5. R: `pthread_kill(t->pt, …)` reads the freed `pt`, then relocks and reads the freed `paused` / `exited`.

Interleaving B, freed by CloseHandle: step 4 before step 3. T exits unclosed, so nothing is freed, then C's CloseHandle frees it.

Either can also happen during step 2 of a pass, while R waits on `T->pcv`. Then `thr_free` destroys a condition variable R is waiting on, and R's return from the wait touches it.

Horizon (checked in Atmosphère's source): `SetThreadActivity` takes `KScopedAutoObject thread = …GetObject<KThread>(thread_handle)` for its whole length (`libmesosphere/source/svc/kern_svc_activity.cpp:49`). `KThread::SetActivity`'s pause loop returns success once the target's termination is requested (`R_SUCCEED_IF(this->IsTerminationRequested())`, `kern_k_thread.cpp:1040`).

## Diff

What it does:
1. `thr_t` gets `int pins` (`:76`).
2. A pause increments it under `G` before its loop (`:1048`), and decrements it after the loop (`:1056`). When it drops the last pin of a thread that is closed and exited, it calls `thr_free`, still under `G`. `thread_exit` (`:404`) and CloseHandle (`:1217`) free only when `pins` is 0.
3. The result is unchanged: 0, as on Horizon for a target that terminates during the pause.

The H3 invariant holds: no new `G` acquisition anywhere. The new `thr_free` call site holds `G` and spins on `cv_pend`, as the other two sites do. Its own deferred queue is empty there, since SVC 0x32 queues no `cv_signal`; `hand_wake` broadcasts directly. Every other queue holder flushes without retaking `G`.

## Test: `dm/host/tests/t_pause_exit.c`

Built like `t_cvsignal.c`: it includes `hle_thread.c` and replaces four calls with macros.
- `pthread_kill(pt, sig)` becomes `slow_kill(&(pt), sig)`. The hook takes the address of `t->pt` and reads it only after the race, which is the same read as the original.
- `pthread_cond_timedwait` lets the race happen while `G` is released, only on the target's `pcv`, then returns `ETIMEDOUT`.
- `free` records the target's free.
- `pthread_exit` records the target's exit.

The target is a real CreateThread / StartThread thread with a C entry (`DM_TEST_THREAD_ENTER`). The handle is closed by a plain host thread through SVC 0x16. The requester is the main guest thread.

Cases:
- 6: the signal window and the wait window, each with three outcomes: closed then exits, exits then closed, closed then pauses (a real `thr_svc_enter`; the test then resumes it by hand, since its handle is gone, and lets it exit). The object must not be freed during the race and must be freed exactly once: by the pause, or at its exit for the paused one.
- `two_pausers`: a second pauser is held in its wait while the main thread's pause sees the exit. The target must survive the first pause and be freed by the second.

Deterministic: each window is forced by its hook, with no timing involved.

## Found on the way, outside H9 (not changed)

From reading the code, not tested:
1. **GetThreadContext3 on an exited thread reads its freed gate frame.**
   - A thread that exits through SVC 0x0A keeps `svc_regs` pointing at its gate frame: `thr_svc_enter` set it, and `thr_svc_leave` never runs.
   - Its gate stack is part of its detached pthread's stack (`thread.c` `guest_gate_stack(1)`), which goes away with the thread.
   - SetThreadActivity marks an already exited target paused at once (`:1046`), and a target that exits during the pause is paused (`thr_svc_enter`) and exited. GetThreadContext3 then passes the `paused` test, and `ctx_fill` reads `svc_regs[0..99]` from that stack.
   - Horizon returns success with a zeroed context for a terminating thread (`KThread::GetThreadContext3`, `kern_k_thread.cpp`: `if (!this->IsTerminationRequested()) GetUserContext(…)`).
   - Candidate item: `ctx_fill` or SVC 0x33 skips the context of an exited thread.
2. **SetThreadActivity on a target that has not started or has already exited returns success.** Horizon returns `ResultInvalidState` (`KThread::SetActivity` requires the state to be Waiting or Runnable). Kept as is: H9 changes no result.
3. **The same lifetime class elsewhere.** GetThreadCoreMask (0x0E), SetThreadCoreMask (0x0F) and GetThreadId (0x25) look up the handle and use the `thr_t` without `G` (host-threads.md, Accesses outside `G`). A CloseHandle and exit on another thread at that moment would free it. Horizon holds a reference there too (`KScopedAutoObject` in `kern_svc_thread.cpp`). That needs a guest that closes a handle while using it, so it is less likely than H9's case.
