## Counting rules

- **Line numbers** are at HEAD. A bare `:N` means `dm/gfx/nvn/nvn_mtl.m:N`.
- **Lines** of a module count every line of the five files: `nvn_mtl.m` 13,110, `nvn_geometry.inc` 862, `nvn_feedback.inc` 85, `nvn_capture.inc` 509 and `nvn_rec.h` 358, 14,924 in all.
  - A line inside a function belongs to that function's module.
  - A line declaring a global belongs to the global's owner.
  - Any other line (comments, types, prototypes) belongs to the next function or global below it.
  - `rt_range_check.inc` is test-only and is not counted (constraint 8).
- **Functions**: 1,107. These are function definitions and ObjC methods: 943 in `nvn_mtl.m`, 78 in `nvn_rec.h`, 44 in `nvn_geometry.inc`, 6 in `nvn_feedback.inc` and 36 in `nvn_capture.inc`.
  - The AST merges all `- dealloc` methods into one key. As a result, the edge dev→sparse (`- dealloc`→`sp_free`) is an artifact and is ignored.
- **Call edges** are distinct caller→callee function pairs across modules: 1,344 after the cuts.
- **Data edges** are distinct (function, global) pairs where the function's module does not own the global: 1,244. Stage I turns them into calls or header inlines.
  - Calls into the diagnostic modules through the hook table, and the six data reads cut in section 2, are not counted.
- **Globals**: 1,064 file-scope variable names in the five files, counted from `vars_summary.tsv`.
  - The "about 400" in the plan counts declaration lines, not names.
  - 6 names are never referenced.
- **Tests**: the `dm/gfx/tests` sources that name one of the module's functions or owned globals.
  - Names shorter than 4 characters and generic ones (`S`, `R`, `draw`, `blit`, ...) are skipped.
  - "wb" counts the subset of tests that `#include "../nvn/nvn_mtl.m"`: 75 sources, 74 tracked plus `t_rec_digest.m`.
  - This is an identifier scan, so it over-counts a little. For S and R, the reliable lists are nvn-state's: 39 tests for T11 and 23 for T12.

## 5. Extraction order

The prerequisite is plan M0: the unity file, `nvn_replay`/`t_capture_live`/`t_rec_digest` linked against module objects, the dependency check and per-file objects.

Then one module per commit, in the numbered order of section 1:

> prof → dev → texfmt → rec → fence → parch → mem → serial → sink → shader → upload → state → hazard → copy → sparse → vin → tex → pso → treg → tbdr → pass → present → ixconv → args → xfer → warm → dump → rewrite → capture → geo → draw → exec → facade

Each cut of section 2 is its own commit inside `nvn_mtl.m`, right before the first module that needs it. Each move is verbatim: code, comments and the module added to `nvn_mtl_all.inc` in its original place.

A step is safe for three reasons:
- every callee and every owned global of the module being moved is already in an extracted module or in the module itself (the matrix is lower-triangular), so nothing extracted calls back into `nvn_mtl.m`;
- the digest is identical: names are given at first reference and addresses are mapped, so a pure move cannot change it;
- the unity file keeps all 75 white-box tests compiling.

## 7. What is left at the end

**`nvn_mtl.m` (facade, about 94 lines plus includes):**
- `mtl_init` as the composition root, calling the per-module init functions in today's order (section 3);
- `mtl_set_frame` (`:1517`), which sets prof's `g_cur_frame`;
- `mtl_drain` (`:1703`), which calls present, upload and fence;
- the lazy-init public wrappers: `mtl_device`, `mtl_pool_add`, `mtl_prepare`, `mtl_pso_prebuild_tool`, `mtl_sub_begin`.

During M it is also the anchor of `nvn_mtl_all.inc`. The alternative of keeping the unity under the name `nvn_mtl.m` (mechanics 2.3) is not recommended.

**`hle_nvn.c` (2,926 lines)** stays the NVN API layer and keeps calling 94 functions:
- 22 of them are declared in `nvn_mtl.h`;
- 46 are declared in `nvn_obj.h`;
- 26 are declared in no header: stats getters such as `mtl_ubd_stats`, `mtl_cut_count`, `mtl_hybrid_stats`, plus weak hooks such as `nvn_game_fps` and `guest_ns`.

The end state:
- **`nvn_mtl.h`** becomes the single C header of the API (no ObjC, or `#ifdef __OBJC__`). It takes the 46 `mtl_*` prototypes out of `nvn_obj.h`, which keeps the shared layouts, and declares the 26 missing ones.
- **No module header** is included by `hle_nvn.c`.
- **Each API function** is defined in its owning module (the "API used by other TUs" column of section 1).
- **Other TUs** keep using `nvn_mtl.h`: `hle_gl.m` 8, `hle_vk.m` 7, `hle_hid.c` 6, `front_mac.m` 6, `hle_os.c` 3, `hle_oe.c` 3, `hle_thread.c` 2, `front_ios.m` 2, and one each in 6 more files.
- **The `g_ft` collision** with `hle_nvn.c`'s static and the `nvn_game_fps` renames stop mattering once `hle_nvn.c` is linked separately (mechanics 2.2, 5).

**`nvn_rec.h`** becomes `mtl_rec.m` plus `mtl_rec.h`:
- the three `@implementation`s, the threads and the ring go into the `.m`;
- the header keeps `rec_on`, `rec_table`, `rec_cb_new`, `rec_commit`, `rec_publish`, `rec_drain`, `rec_signal`, `ubc_*` and the `RO_*` enum the digest sink reads (mechanics 2.2);
- at stage SK it becomes the recorder sink behind the sink module's interface.
