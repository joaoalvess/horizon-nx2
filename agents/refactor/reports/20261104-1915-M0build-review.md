# M0 build stream review (part 5 and D5)

Worktree `rf-m0-build`, uncommitted diff on `2c0b0c9e`. Read-only: `make -n` / `make -n -B` dry runs of the new and old Makefile (`git show HEAD:dm/host/Makefile`, run with `-f` from `dm/host`), the existing `.d` files under `dm/host/gen/*/obj`, and a scratch mtime test of `/usr/bin/make`. I built nothing and ran no tests. An early repository-wide `rg` printed a few lines of `reports/20261104-1808-M0build-impl.md`. I did not open the file, and every finding below comes from the code.

**Verdict: approve with nits.** F1 is a real gap in the NSP script's reuse key, with a one-line fix. Fix it before the join.

## Findings

**F1 (medium). `scripts/build_ipa_from_nsp.py:1308-1322`: the Mac host's reuse key no longer covers the compile flags.**
- `cmd` is now the link line (`Makefile:95`), and `common` and `decoder` fingerprint only that line, the files of `HOST_DIRS` and the generated headers and libraries. Before the diff, `cmd` was the single compile line, so every compile flag was keyed.
- `HOST_CC` (`Makefile:83`) holds what the link line lacks: the `-I` list, plus anything added later to the compiles only (a `-D` switch, `-fno-…`, a new include folder). `dm/host/Makefile` is not fingerprinted either, because `srcs` keeps only `.c .m .h .S .inc`.
- Failure: someone adds `-DNVN_SOMETHING=0` to `HOST_CC`. `make host_obj` (line 1307) recompiles every object, because `Makefile` is a prerequisite. The key still matches, so line 1322 returns the old `<id>_build/tools/dmhost`, and the `.decoder.json` record keeps claiming the old inputs. The NSP script then boots a host that does not match the tree, with no message.
- Fix: fingerprint the host compile lines of `dry.stdout` (the `-c … -o gen/<id>/obj/…` lines) together with `cmd`, or add `host / 'Makefile'` to the `files` item. The docstring (lines 1302-1304, "Reused when the compile line …") then reads true again.

**F2 (low). `scripts/build_ipa_from_nsp.py:1307` vs `1322`: the reuse path compiles the whole host first.**
- `host_obj` runs before the reuse check. When `dm/host/gen/<id>/obj` is missing (a fresh clone, or after `make clean`), or when the profile header is rewritten (a derived or provisional profile after a repo-profile build, or the reverse), it compiles up to 70 files and then returns the existing binary unchanged.
- Before the diff, the reuse check came before any compile.
- Fix: run `host_obj` only once the key differs. The key needs only the profile header, the MSL header and the libraries, which the first `make` already produces.

**F3 (low). `scripts/build_ipa_from_nsp.py:1324-1325` with `Makefile:94,97`: the script's link shares the Makefile's LTO temporary folder.**
- The link line from `make -n` carries `-Wl,-object_path_lto,gen/<id>/obj/lto`, so the script's `ld` and `dsymutil` use the same directory that `make dmhost` deletes before and after its own link.
- The script never removes it: `dm/host/gen/0400A3A01EE4C000/obj/lto` holds 67 `*.thinlto.o` files (about 18 MB) from 18:47.
- Failure: the user runs the NSP script for a game while `make -C dm/host GAME=<same id> dmhost` runs (the guard serializes only the agents' jobs). The `rm -rf` at `Makefile:94`/`97` then deletes the objects the script's `ld` or `dsymutil` is reading. Result: a failed link, or a `dmhost.dSYM` without debug info.
- Fix: replace that argument in `cmd` with a folder beside `out` (for example `out.with_name(out.name + '.lto')`), and remove the folder after `dsymutil`.

**F4 (nit). `dm/ios/tools/gen_build.py:43`: stdout is not identical, as the plan's criterion asks.**
- Parsing the old and new `make -n -B dmhost MSL_SDK=iphoneos` with gen_build's own logic (Pokopia) gives:
  - sources: 257 = 257, same order, so the `Gen/src` listing is unchanged;
  - `-I`: 10 = 10, same order;
  - frameworks: 13 = 13;
  - `-D`: loses `-DDM_HOST_REV="2c0b0c9e-dirty"`, so the line becomes `OTHER_CFLAGS = $(inherited) `.
- This is harmless. The only reader, `stream_mac.m`, never reaches iOS (the `_mac` filter, `gen_build.py:37`, `compile_check.py:28`), and the xcconfig no longer changes at every commit.
- The plan's M0 row says "same stdout", so the main thread should record this as accepted.

**F5 (nit). `docs/development.md:648`: "each profile has its own objects" is inaccurate.**
- Objects are per title ID (`gen/<id>/obj`). A derived or provisional profile of the same ID (`DM_GAMES_DIR` / `DM_GAMES_FIRST`) shares them with `dm/games/<id>`. Only the rewritten `game_profile.h` and the `.d` files keep the two apart.
- Suggest "each game (title ID) has its own objects".

**F6 (nit). Wording the diff made stale:**
- `scripts/build_ipa_from_nsp.py:1287`: the `HOST_DIRS` comment still cites `GFX_H`, which the diff deletes.
- `dm/mac/min_os.mk:1`: "the NSP script runs the same line, make -n". The minimum version is still on both the compile and the link lines, so this is only wording.
- `docs/reference/memory.md:400`: cites "refactor decision D5", a label from `agents/`, in a reference entry.

## Checked and holds

**Objects never cross games.**
- `OBJ = gen/$(GAME)/obj`, and `dmhost` and the NSP link line take only that game's objects. Both of the script's `make` calls get the same `env`.
- `gen/game.stamp` still forces the shared `dm/host/dmhost` to relink on a game change (`Makefile:71-74`). `host_obj` touches neither the stamp nor `dm/host/dmhost`.
- For the same ID with another profile, `game_profile.h` is rewritten only when it changes (FORCE, `game.py header`). It appears in the `.d` of every file that includes it, so those files recompile.
- No `.d` names anything under `gen/<id>/profile`, and the per-game include folder holds only `game_profile.h` and `host_rev.h`.
- `/usr/bin/make` is 3.81 and compares whole seconds: a prerequisite 0.6 s newer in the same second does not rebuild (scratch test). The same-second window that `Makefile:65-67` describes therefore now applies per object. Only two `make host_obj` runs with different profiles of one ID within one second reach it, and it is no worse than before.

**The dependency files catch every header.**
- There are 70 objects and 70 `.d` files for Pokopia.
- `nvn_mtl.m.d` lists `nvn_feedback.inc`, `nvn_geometry.inc`, `nvn_capture.inc`, `dmsh_chain.h` and `gen/<id>/game_profile.h` (no `//`, so the FORCE rule matches).
- `rt_range_check.inc` is absent, correctly: it is included only under `#ifdef NVN_RT_RANGE_TEST` (`nvn_mtl.m:13097`).
- `host_msl.m.d` lists `host_msl_gen.h`, `stream_mac.m.d` lists `host_rev.h`, and `hle_movie.c.d` lists `stb_vorbis.c`.
- Every header of the old explicit list, and every `*.h` in `dm/host`, `gfx/nvn`, `nvn/include` and `gfx/tex`, appears in some `.d`, except `romfs_identity.h`, which only iOS's `main.m` includes.
- No host source uses `.incbin` or `#embed`.
- `-MP` keeps a deleted header from stopping the build.

**`host_rev.h`.**
- `cmp -s` then `echo >` rewrites it only when `git describe --always --dirty` changes, and only `stream_mac.m.o` depends on it.
- The `__has_include` fallback holds for every consumer:
  - the host: `REV_H` is an order-only prerequisite of every object, so it always exists before `stream_mac.m` compiles;
  - `t_stream` and `t_stream_sock` (`dm/gfx/tests`, `-I../../host/gen/<id>/`): they get the last host build's revision, or `"unknown"`, and no test reads the value;
  - lint's compile database: the same;
  - iOS: never compiles `stream_mac.m`.
- `git describe` failing gives `""`, as the old `-D` did.
- One effect to know: a host the NSP script reuses keeps reporting the revision it was linked at. Before, every new `git describe` (any tracked edit makes the tree `-dirty`) relinked it.

**The flags per file match the old command.**
- Token by token on the dry runs, each compile equals the old single command minus `-Wl,-export_dynamic` and `-DDM_HOST_REV`, plus `-MMD -MP`, in the same order. There is one distinct flag set for all 70 files, and the sources are in the same order.
- The link equals the old command minus `-I` and `-D`, plus `-Wl,-object_path_lto,…`.
- The explicit `-object_path_lto` and `dsymutil` replace what the clang driver added only when it compiled sources itself, so the result is equivalent.

**iOS Release only.**
- The stream's generated `ios-d5/project/DmIOS.xcodeproj` has, at project level:
  - Release: `GCC_OPTIMIZATION_LEVEL = 2` and `LLVM_LTO = YES_THIN`;
  - Debug: `GCC_OPTIMIZATION_LEVEL = 0` (XcodeGen preset).
- The target configs set only `OTHER_CFLAGS`.
- Nothing overrides them: `Gen/dm.xcconfig` (gen_build stdout, `OTHER_LDFLAGS`, `DM_APPICON`, …), the `project.yml` target settings and `build_ipa.sh:156-158`'s `xcodebuild` line set neither key.
- `ios_d5.log` shows `-flto=thin`, ` -O2 ` and `BUILD SUCCEEDED`. `ios_base.log` shows `-Os`.

**NSP script from a fresh build folder.**
- The dry run's `' -o dmhost '` matches the link line. The first `-o` is the output, since `-Wl,-object_path_lto,…` is a single token.
- `ld` creates the LTO folder, which the Makefile's own link also relies on, since it deletes the folder just before linking.
- `dsymutil` writes `<out>.dSYM`, as the driver did before.

**NSP script from an existing build folder.**
- A folder from before the diff relinks once, because its key changes.
- A folder from the new scheme is reused (subject to F1 and F2).
- The test fakes in `test_host_msl.py` skip `dsymutil` and still check reuse by key.

**No `make -j` race.**
- `GAME_H`, `REV_H` and `MSL_H` are order-only for every object and built once per run. `game.py header` uses `exist_ok`, and the object rules use `mkdir -p`.
- The NSP script's single `make` names every goal once.
- The `.d` files have no rule, so `-include` triggers no remake.

**Other callers.**
- `lint_c.py` compdb: drops `-o` and `-Wl,` and keeps `-MMD -MP`, which clang-tidy strips. The link line yields no entries.
- `regress.py` keys on `dm/host/Makefile`, so it is unaffected.
- CI's `make -j3 dmhost`: unaffected.
- No added comments and no debug leftovers. Existing comments were reworded only where the diff made them wrong.

**One trap for later checks.** `make -n` without `-B` shows every object as out of date, because under `-n` make assumes the FORCE header rules updated their files. It is not a real rebuild, so do not use `make -n` to judge incrementality.
