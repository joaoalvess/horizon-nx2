### 6. Nit (performance, small): an atomic exchange on every thread SVC

`svc_thread` runs `atomic_exchange(&me->start_wait, 0)` on every guest thread SVC (`hle_thread.c:970`). That is a seq_cst read-modify-write (an LSE `swpal`) on the hot path, though `start_wait` is almost always 0. A relaxed load in front of it, `atomic_load_explicit(..., relaxed) && atomic_exchange(...)`, would skip the write in the common case without losing a wake: the requester's store still pairs with the exchange whenever the load sees 1, and otherwise the 50 µs re-check bounds the wait. The cost is a few nanoseconds per SVC at 75-90 k SVC/s. It is listed only because H3 counted its own per-SVC cost.

### 7. Nit (performance, mode not used by the fork's games): an O(threads) scan under `G` per `hand_wake` in all-peers mode

The H5 review's nit 1 (a broadcast on every state change) is fixed: the revised `hand_wake` (`:146-156`) broadcasts only when the thread can end some waiter's wait, and `note_runnable` calls it only in handoff mode (`:264`). In all-peers mode, though, each `hand_leave` / exit / priority change / pause while `g_hand_waiters > 0` now walks all of `g_all` under `G` (`:153-154`). With about 90 threads that is a few hundred ns per call. No profile of Pokopia, DK or MKW sets `core_preempt`. A per-core waiter count would bound the walk if all-peers mode is ever used.

### H3 invariant: no `G` between a release and its `cv_flush`

Every path that queues (`wake` from `lock_handoff`, `lock_acquire_for`, 0x35, `wake_sync_waiters`, 0x19; `cv_signal` from StartThread and `dm_guest_clock_advanced`) ends its hold in one of these:
- `svc_thread_impl`'s single `G` section, then `cv_flush` (`:959-960`);
- `thread_exit` (`:404-405`), before `pthread_exit`;
- `dm_guest_clock_advanced` (`:620-621`);
- `hle_signal_system_event_binding`, `hle_signal_system_event` and `hle_signal_bound_system_event` (`:1266-1267`, `:1279-1280`, `:1298-1299`);
- `block`'s flush under `G` before its wait (`:298`).

Within `svc_thread_impl`, no case that queues takes `G` twice. The only cases with two sections or an inner unlock are 0x08 (it queues nothing) and 0x32's `pthread_kill` loop. 0x32's hold calls `hand_wake`, which broadcasts at once and is not deferred. `poll_wait_end`, which runs between 0x1C / 0x18 / 0x34's unlock and the flush, takes no lock.

H5 adds two `G` sections to `svc_thread`: `dm_yield_to_core_peers` and the `start_wait` broadcast. Both come after `cv_flush`. The new implicit releases of `G` (the `g_hand_cv` waits at `:180` and `:217`) run with an empty queue:
- `dm_thread_service_request` is entered from HLE code outside any SVC;
- `dm_yield_to_core_peers` runs after the flush, and its hold queues nothing.

`svc_thread_impl` is reached only through `svc_thread` (`hle_svc.c:458`). `wake`, `cv_signal` and the other queueing functions are static.

### Lost wake-ups

- **Guest waits.** `woke` and `started` are written under `G` before the signal is queued, and every waiter re-checks them under `G` (`:299-307`, `:380`). So a late signal finds the waiter either already in `pthread_cond_wait` or about to see the flag. A late signal that lands in the same thread's next wait is a spurious wake, which the `while (!t->woke)` loop absorbs. The detclock path waits without a timeout and re-checks its guest deadline on every wake.
- **Handoff wait.**
  - In `dm_yield_to_core_peers` the scan, `hand_wait` / `g_hand_waiters` and the wait are one hold of `G` (`:214-218`). So a writer under `G` either runs before the scan, which sees it, or runs after the waiter is queued on `g_hand_cv`, which its broadcast reaches.
  - I checked each writer that can end the wait: `exited` (`:400`); `wkind` through `block` → `hand_leave` (`:292`); `native_wait` (`:194`, `:173-175`, the same hold); `pause_req` (`:1043`); `prio`, tested before the write (`:1022`); `nhand` (`hand_leave`, `note_runnable` `:264`). Each one calls `hand_wake` under `G` with a test that matches the scan's predicate (`:216`):
    - handoff mode: `thr_in_handoff` against each `hand[i]`, plus `prio` and the core bit;
    - all-peers mode: `prio` and the core bit for every waiter.
  - `hand_wake` tests no `started` / `exited` / `runnable` state, so it can only broadcast too often, never too seldom.
  - Fields written without `G` (`*host_work`, `sleeping`, `host_owned`, SetThreadCoreMask's `core` / `mask`) are caught by the 50 µs bound, which is kept. A missed broadcast therefore costs at most what HEAD's poll cost before H5, and never hangs.
- **Service-request wait (`start_wait`).** The requester stores `start_by->start_wait = 1` (seq_cst) and then loads `hand_epoch`, under `G` (`:178-179`). The starter increments `hand_epoch` (a seq_cst RMW, `:969`) and then exchanges `start_wait` (`:970`).
  - If the requester's load sees the old epoch, its store precedes the starter's exchange in the single total order, so the exchange reads 1 and the starter broadcasts.
  - The starter must take `G` for that broadcast, so it cannot land before the requester is queued on `g_hand_cv`.
  - A `start_wait` left at 1 after the requester breaks out costs one spare broadcast at the starter's next SVC.

### `thr_free` against queued signals and `g_hand_cv` waiters

- **Signals.** `cv_pend` is incremented under `G` (relaxed, ordered by the mutex) and decremented by `cv_flush` with release after `pthread_cond_signal` returns (`:281`). `thr_free` loads it with acquire under `G` before `pthread_cond_destroy` (`:392-393`). Signals sent at once past 16 are sent under `G`, so they cannot overlap the free.
- **No self-deadlock.** `thread_exit` frees itself (`:403`) after queueing only for kind-4 waiters, which are linked and so not exited. CloseHandle (`:1214`) queues nothing. `thr_free` never runs on a thread that is in its caller's own queue.
- **The spin ends.** `thr_free` spins holding `G`, and no flush needs `G`.
- **`g_hand_cv` waiters keep no pointers to other threads across the wait**, apart from `dm_thread_service_request`'s `me->start_by`. `thr_free` clears every `start_by` that points at the freed thread (`:390`), and the loop re-tests `me->start_by` before it dereferences it (`:177-178`).
  - `hand_wake` dereferences `t->hand[i].by`. `thr_free` removes every such entry for the freed thread (`:389`).
  - A thread inside the handoff wait is inside an SVC, so it cannot be exited or freed. `g_hand_cv` is static and never destroyed.

### All-peers mode against handoff mode

- `svc_thread` passes `g_core_preempt` as `all` (`:966`). `dm_yield_to_core_peers` has no other caller (`rg` finds only a comment in `hle_guestthread.c`), so the mode `hand_wake` keys on (`g_core_preempt`) is always the waiter's mode.
- In handoff mode, the wake from `note_runnable` (`:264`) covers a runnable thread whose `nhand` is reset while it is in a waiter's handoff: StartThread on a running thread, or a WaitSynchronization waiter woken and blocking again (`:1189`, through `hand_leave`).
- In all-peers mode `note_runnable` cannot end a wait, and it no longer broadcasts.
- A sleeping peer in all-peers mode with `nhand` 0 is seen only at the re-check. The H5 review's observation 4 still holds; the latency is HEAD's.
