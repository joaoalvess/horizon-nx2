### What changed
- **M1 (`nvn_replay.m`):**
  - I confirmed the mechanism in the code:
    - `apply_env` copies `DM_SAVE` and `DM_PSO_ARCHIVE` from the capture;
    - `pso_user_path()` then gives `<work>/runs/pso_user.tsv`;
    - `pso4_init` gives `<work>/runs/pso_archive`;
    - the prebuild (`dispatch_group_async`) and `arch_flush` (`dispatch_after`) stay outside the shim.
  - **Fix:** right after `apply_env`, under `--digest`, `rdg_state_take()`:
    1. makes `<capture>.digest.XXXXXX` beside the capture;
    2. clones the live user list and archive into it, with the same path rules as the replay layer;
    3. sets `DM_PSO_USER`, `DM_PSO_ARCHIVE` (unless the archive is `off`) and `DM_PSO_PREBUILD=0`;
    4. removes the folder at exit.
  - This happens once per process, so each `--repeat` child gets its own copy. If the copy fails, the replayer stops with `[RED]` and exit 2.
  - No change to `nvn_mtl.m`.
- **Docs (`development.md`):**
  - **Inline now:** the `dispatch_async` blocks only, by name: `sm_amp_get` amplified pipelines, mesh pipelines, `pso_pend_kick` / `pso_pend_demand` builds, the hybrid's pulling bases, and the `warm_start` pipeline prewarm.
  - **Not inline:** the prebuild workers (turned off) and the archive's delayed flush (it writes only the copy). The per-process copies are described.
  - The shader prefetch is dropped.
- **N1:** the unnamed-ID list now includes `ms_after` (`DM_NVN_MAGSCAN`).
- **N2b:** a new check in `t_rec_digest.m`:
  1. free a resident buffer whose table entry was built;
  2. assert that `rdg_buf_at` drops the dead entry;
  3. allocate until a new buffer takes the same GPU address;
  4. make it resident and check it is found and named, with no unresolved addresses and the same digest. It prints `skip:` if the address is never reused.
- **N2a:** new `dm/gfx/tests/test_rec_layout.py` (CPU only), run by `check_test_rec_layout`, which is in `run:`.
  - It reads every record site in `nvn_rec.h` and `nvn_mtl.m` (57 sites, 52 ops): writes into `a[k]`, `rec_table_op`, and `memcpy` of `MTLViewport` / `MTLScissorRect`.
  - It asserts:
    - each layout's length equals the slots its records write;
    - a slot that a site never writes has the letter `-`;
    - letters match the slot's kind (object, pointer or value);
    - `m` has its count slot;
    - every enum op has both a layout and a site.
  - Mutation check: an added argument, a dropped write and an object in a raw slot were each caught.
  - `RO_NOTE`'s layout became `"--"`. The digest bytes are unchanged, since `-` hashes nothing.
- **N3:** `check_t_rec_digest: RUN_ENV = MTL_DEBUG_LAYER=1`.
- **N4:** the duplicate `<objc/runtime.h>` import is removed, and the header usage line lists `--digest`, `--digest-expect` and `--digest-dump`.
