# R3 impl: replays answer the sdk's Switch 2 flag and the GOB order as the live run did

Branch `refactor`, not committed. Base of the diff: `7421ef5f`, then `59d2272e` (C7, committed meanwhile; the candidate binaries contain it). Another item's uncommitted diff in `dm/gfx/nvn/nvn_geometry.inc` appeared at 06:46, after my last build; it is not mine and is not in any binary below.

## Root cause, verified before any change

- `dm_sdk_ounce` has one strong definition, `dm/host/loader.c:151` (it scans the sdk module for `spec: Ounce`). `hle_nvn.c:184` has a weak one that returns 0. No file under `dm/gfx` defines it. `nvn_replay` links `MTL_T_SRC` minus `hle_nvn.c`, which it includes, so only the weak one is left: before the fix `nm -m nvn_replay` showed `weak external _dm_sdk_ounce`.
- `nvn_gob_switch2` is set only in `nvnDeviceInitialize` (`hle_nvn.c:127`), and tests set it directly. The replayer never calls `nvnDeviceInitialize`, so its value stays 0. Both deswizzle paths read it: `nvn_deswizzle.c:14,61` and `nvn_deswizzle_gpu.m:39,56,78`.
- The capture recorded neither value. HEAD has format, iface, chain, commit, title, build, frame and env. STAT has tex_pool_n, origin_ll, queue_origin_ll and depth_zero.
- `dm_sdk_nvn2_item`, `dm_sdk_major` and `dm_glslc_gpu_code` are needed by nothing in the replay layer. They are reached only from `nvn_api` and `nvnDeviceGetInteger` (`hle_nvn.c:187-220`), that is, from the game's own queries, and the replayer never calls those. What the game did with the answers is already in the captured records and pools. So R3 records and answers only `dm_sdk_ounce` (`nvn_mtl.m:8173`, `:10897`) and the GOB order. `hle_nvn.c` is unchanged.

## What the diff does

1. The capture records what the replay layer reads outside the records: the sdk's Switch 2 flag and the GOB order.
2. The replayer answers `dm_sdk_ounce()` and sets `nvn_gob_switch2` from the capture before any upload. So storage-uploaded textures are deswizzled in the live run's order, and NVN2 compute dispatches get their dims at `c0 + 4`.
3. Older captures do not carry the flag. They are refused unless `--sdk-ounce` states it.

## Older captures: what I chose and why

Nothing an older capture holds determines the sdk's spec:
- **The profile's `build` rows** pin main's build ID to the sdk's build ID, but no profile key or table records whether that sdk is `Ounce`; the game.tsv comments are not data.
- **The title ID's `04` prefix** is a naming convention, not a fact about the sdk module.
- **The sdk module itself** is not in the capture. The build folder's modules (`DM_ROOT` in the header env) are rewritten and keyed (`patched_v*.key`).
- **The programs** carry only key hashes. The NVN2 control-section version (`0xc9`) is not in the capture.

The record that does hold the fact is the live run's own log: `loader.c` prints `sdk: built for the Switch 2 (spec: Ounce)` when it returns 1.

So the replayer refuses such a capture by default with a clear `[RED]` line. With `--sdk-ounce 1|0`, it replays it as the live run did, the value taken from that log. All 18 capture-boot logs of tonight's corpus (`<work>/runs/s0_pk_*_f*.log`, `s0_dk_*_f*.log`) contain the line. So every capture on disk now replays correctly with `--sdk-ounce 1`, and no recapture is needed.

Format: no `CAP_VERSION` bump. This follows `iface`: a new key, whose absence the new replayer checks. Old replayers ignore the keys, so they still replay a Switch 2 capture with Switch 1's order, as before.

## What did not hold, and open points

- **No in-capture fact gives the flag for older captures**, so every capture made before R3 needs `--sdk-ounce 1` with R3 replayers, and exits 2 without it. That covers all of `captures.md` and the Switch 1 games' captures, if any are on disk (none on this Mac).
  - The `commands.md` replay commands need the flag, or new captures with `base-b0d98ee7-cap`.
  - `regress.py replay` reports exit 2 as an ERROR asking for a new capture.
  - An old replayer, such as `head-*` before R3 or `nvn_replay_count_r1`, rejects `--sdk-ounce` as an unknown option (usage, exit 2). Do not pass it to those.
  - Any `nvn_replay` built from this working tree from now on contains R3, so other items' scripts that replay older captures must pass `--sdk-ounce 1`. At 07:15, P2's run (`scratchpad/p2/rp.sh`) was replaying with `cand-P2` and `cand-C7`; neither has the R3 strings, so that run is unaffected.
